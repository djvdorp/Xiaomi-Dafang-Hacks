# Issue 1435: 8189ES candidate

## Status

Built and statically checked. The candidate remains opt-in. A guarded live
swap was attempted, but SSH dropped and the timed rollback did not restore
reachability; whether the candidate loaded is unverified. Keep the stock driver
as the boot default.

## Build and checks

Build with `ARCH=mips`, `CONFIG_PLATFORM_MIPS_JZ4760=y`, `CONFIG_SDIO_HCI=y`,
and `KSRC` pointing at the prepared 3.10.14 tree. The pinned driver Makefile
has one build-only workaround: remove `EXTRA_CFLAGS += $(ccflags-y)`. Kernel
3.10 already imports `EXTRA_CFLAGS` into `ccflags-y`; this duplicate creates a
recursive Make variable. No runtime driver source was patched.

The resulting [`8189es-candidate.ko`](../../firmware_mod/driver/8189es-candidate.ko)
is a 2,704,104-byte 32-bit little-endian MIPS relocatable module. Its reported
version is `v5.8.9_35085.20190919` and its vermagic is
`3.10.14 preempt mod_unload MIPS32_R1 32BIT`.

All 171 undefined kernel symbols referenced by the candidate have matching
`__ksymtab` entries in the running camera's `/proc/kallsyms`. This is a static
export check; runtime Wi-Fi behavior still needs the camera test.

SHA256: `e31be01ce16257cfed7df88ce235bf57d573063ee177e19816455f105ab76b7a`

Run `tests/issue-1435-artifacts.sh` to check the artifact architecture,
version, vermagic, and documented hash.

## Live camera results (2026-10-31)

Stock RTSP was decoded from the host over TCP for 10 minutes at the original
camera config: 29,851 frames decoded, 8 lost, and 4,786.7 kb/s mean bitrate.
The run was labeled 1280x720 from the config, but the old camera controller
reads `RTSPOPTS` while the config requested that size through `RTSPH264OPTS`;
the actual baseline resolution was not captured separately.

With explicit `RTSPOPTS="-W960 -H540"`, VLC reported 960x540 at 25 fps for 10
minutes: 30,165 decoded, 9 lost, and 4,925.5 kb/s mean bitrate. Neither run
stalled. The 960x540 run did not reduce measured bitrate or frame loss versus
the baseline; the uncaptured baseline resolution limits this comparison.

The watchdog was enabled temporarily with a 10-second interval and a 15-second
probe timeout. The camera's `avconv` consumed H.264 NAL data but failed to
produce the packet-copy output file on a stream that VLC decoded. The watchdog
restarted RTSP twice, reached its retry limit, and stopped; the camera did not
reboot. The watchdog is therefore disabled by default until a compatible
healthy-stream probe is verified on the target firmware.

Shell-side follow-up tests cover stock fallback when a selected RTSP candidate
exits during startup. Watchdog restarts record the RTSP process start time,
refuse to signal a PID whose identity is missing or changed, and stop recording
before restarting RTSP. These checks use stubbed processes; they are not live
camera validation.

Before the driver trial, the stock module was backed up as
`/tmp/issue1435-backup/8189es-stock.ko`, and the candidate stayed at
`/system/sdcard/driver/8189es-candidate.ko`. A detached stock rollback was
armed. SSH at `192.168.1.38` did not return after the swap or rollback window;
candidate load, Wi-Fi association, RTSP, and post-test `dmesg` are unverified.
Persistent camera config was left at its stock driver default. The camera is
currently unreachable from the host; a power cycle should reload its stock
boot driver, but that recovery is not verified.

If SSH is available while the candidate is loaded, restore stock with:

```sh
. /system/sdcard/scripts/wifi.sh
mac=$(get_wifi_mac)
station_stop
rmmod 8189es
insmod /driver/8189es.ko rtw_initmac="$mac"
station_start
```
