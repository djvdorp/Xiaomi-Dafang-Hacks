# Issue 1435 Hybrid Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Dafang RTSP stream recover from video stalls while safely testing a newer T20-compatible `8189es` driver and a newer MIPS RTSP/live555 binary.

**Architecture:** Keep stock artifacts as defaults. Add opt-in SD-card driver and RTSP-binary selectors with explicit fallback. Add a bounded local `avconv` probe that restarts only RTSP after confirmed video failure, then validate candidates on the real camera before enabling them.

**Tech Stack:** POSIX shell/BusyBox, Ingenic T20 Linux `3.10.14` MIPS kernel, Realtek SDIO driver source, MIPS/uClibc ELF binaries, VLC/FFmpeg host-side validation.

**Spec:** `docs/superpowers/specs/2026-10-31-issue-1435-hybrid-design.md`

## Global Constraints

- The camera runs Linux `3.10.14 #21 PREEMPT`, MIPS, with stock `8189es v4.3.18.3_20185.20161116`.
- Candidate driver builds must use the matching kernel tree and toolchain.
- Stock driver and RTSP binary remain available as fallbacks.
- Candidate files are staged under distinct names before activation.
- RTSP recovery must not reboot the camera or restart Wi-Fi.
- No credentials or RTSP URLs containing credentials enter git.

## Review Focus

- Missing candidate driver: boot must use `/driver/8189es.ko`.
- Failed candidate `insmod`: boot must continue with stock Wi-Fi and log the fallback.
- Missing candidate RTSP binary/library directory: RTSP must use the stock binary and library path.
- A live RTSP process with no decodable frame: watchdog must restart RTSP once after the configured timeout.
- Repeated failed probes: watchdog must stop retrying after the configured limit.
